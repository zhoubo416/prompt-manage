# Design

本目录存放项目、子项目和组件的设计文档,描述结构、职责、接口和关键取舍。修改相关范围前必须先阅读对应设计。

- 仓库整体设计以及跨多个子系统的设计直接放在本目录。
- 每个子系统或组件自己的设计放在 `docs/design/<name>`。
- 一份设计涉及同级多个子系统或组件时,放在这些范围最近的共同上级目录,不任意归到其中一个。
- 大型设计的 `README.md` 是该范围的目录,先读入口再按任务读章节;存在明确阅读顺序时章节文件用两位数字开头,例如 `00-system-design.md`,没有章节顺序的文档不加数字。
- 设计文档使用稳定的语义化路径,文件名用英文和连字符,不用日期命名。
- 只有设计文档写"修改历史",按日期倒序记录影响设计含义、边界或行为的重要变化,措辞和格式调整不记录。
- 根 `AGENTS.md` 或上级设计 README 维护对应索引,新增设计时同步登记。

## 设计索引

本目录的设计按阅读顺序编号,改动相关范围前先读对应文档。

- **系统整体设计** (`00-system-design.md`) — 系统定位、第一版范围、子系统划分、Tenant 隔离、角色权限和关键取舍。
- **数据模型** (`01-data-model.md`) — 数据表、字段职责、关系、唯一约束和状态枚举。
- **Prompt 对外 API** (`02-prompt-api.md`) — 业务系统获取 Prompt 的接口、认证流程、返回字段和调用统计口径。
- **管理后台** (`03-web-console.md`) — 后台页面结构、页面职责和关键交互约定。
- **服务端结构** (`04-server-architecture.md`) — 代码目录划分、请求处理流程、认证与租户隔离实现、数据库访问方式。

产品范围、页面原型和第一版边界以 `../Prompt 管理系统产品说明书.md` 为准。
