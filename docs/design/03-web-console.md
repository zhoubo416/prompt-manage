# 管理后台

本篇描述管理后台的页面结构、页面职责和关键交互约定。产品原型见 `docs/Prompt 管理系统产品说明书.md` 的第六到第十章和第十六、十七章,整体结构见 `00-system-design.md`。

## 页面结构

系统首页默认进入 Prompt 管理。后台一共六个页面:

| 页面 | 职责 |
|---|---|
| Prompt 列表 | 按分类筛选、搜索名称或 Key、查看版本与调用次数、进入详情、新建 |
| Prompt 创建 / 编辑 | 填写名称、Key、分类、描述、Prompt 正文,定义变量,保存草稿或发布 |
| Prompt 详情 | 展示元信息、当前版本、正文、变量、版本历史和调用统计,提供编辑与新建版本入口 |
| 分类管理 | 创建、改名、调序、删除分类 |
| API Keys | 创建、查看、禁用、删除 API Key |
| Analytics | 按今日、本周、本月、全部查看调用量和 Prompt 调用排行 |

## 路由与页面

| 路由 | 页面 |
|---|---|
| `/login` | 登录与注册,注册时同时创建账号、租户和 Owner 成员 |
| `/prompts` | Prompt 列表,首页默认跳到这里 |
| `/prompts/new` | 新建 Prompt |
| `/prompts/[id]` | 详情:当前版本、变量、版本历史、调用次数、调用示例 |
| `/prompts/[id]/edit` | 编辑:基本信息与正文一起保存,保存生成草稿,发布才对外生效 |
| `/categories` | 分类管理 |
| `/api-keys` | API Key 管理 |
| `/analytics` | Usage 统计 |

整体是左侧导航加右侧内容区的后台布局,顶部显示当前邮箱和角色。没有登录时统一跳转到 `/login`。

## 关键交互约定

- **分类删除必须先迁移**。分类下存在 Prompt 时不允许直接删除,先让用户选择目标分类把 Prompt 迁走,避免 Prompt 失去归属。
- **Key 创建后只完整展示一次**。生成成功时把完整 Key 展示给用户并提示保存,之后列表只显示前缀、创建时间、最后使用时间和状态。
- **变量从正文自动识别**。从 `{{name}}` 中提取变量,用户只需要补充类型、是否必填和说明,第一版类型只提供 Text。
- **模板预览只做变量替换**。编辑页填入样例值后生成最终 Prompt,用于检查变量替换是否正确;第一版不调用大模型。
- **版本不可覆盖**。编辑已发布 Prompt 时保存为新的 Draft 版本,发布后原来的 Published 版本转为 Archived。
- **权限决定入口可见性**。删除 Prompt 和 API Key 管理只对 Owner、Admin 开放,成员看不到这两个入口;前端隐藏入口不能替代服务端权限判断。
- **保存和发布分开**。编辑页的「保存草稿」只写草稿,「发布」才会成为对外提供的版本,页面上明确写清两者的差别。
